# Лабораторна робота №7 — Вебпошук на FastAPI

**Курс:** Python — побудова пошукової системи. **Версія:** `0.7.0`. **Git-мітка:** `lab-07`.

**Оригінальна методичка:** https://github.com/rmalkevy/Programming-Practice-Projects/blob/main/courses/python/lab-07-fastapi-web-search.md

Це **окремий самодостатній проєкт**, що використовує необхідну основу `findex` із попередніх лабораторних, але містить реалізацію лише завдань сьомої лабораторної: HTTP API, графічний пошук, типізовану валідацію, конфігурацію, Docker і перевірки.

> **Стан здачі:** локальна реалізація і тести завершені. **Публічне розгортання не виконано** — потрібен ваш акаунт на Render/Fly.io/Railway, доступ до Docker і завантаження коду в GitHub. Вимірювання `oha` на реальному сервері також треба виконати окремо. Не вказуйте URL чи значення p95/p99 реального сервера, доки не виміряєте їх.

## 1. Встановлення і запуск

Потрібно: Python 3.12+, інтернет для першого встановлення, термінал. У корені розпакованого проєкту:

```bash
python -m pip install -e . pytest httpx
python -m findex.cli index data/demo --out data/demo.json
python -m findex.cli serve --port 8000
```

Відкрийте у браузері:

- **http://127.0.0.1:8000/** — вебпошук українською.
- **http://127.0.0.1:8000/docs** — автоматична документація OpenAPI.
- **http://127.0.0.1:8000/health** — перевірка працездатності.
- **http://127.0.0.1:8000/search?q=python&k=5&scorer=bm25&page=1** — пошуковий API.

Альтернативно, за наявності `uv`:

```bash
uv sync --dev
uv run findex index data/demo --out data/demo.json
uv run findex serve --port 8000
uv run pytest -q
```

Файл `uv.lock` не вдалось створити офлайн: залежності FastAPI відсутні в локальному кеші `uv`. На вашому ПК після `uv sync --dev` він має з'явитися; додайте його до репозиторію.

## 2. Реалізовані кінцеві точки

| Метод | Шлях | Призначення |
|---|---|---|
| GET | `/search` | Пошук із параметрами `q` (1–200 символів), `k` (1–100), `scorer` (`bm25`/`tfidf`), `page` (від 1) |
| GET | `/docs/{doc_id}` | Вміст документа; HTTP 404, якщо немає |
| GET | `/stats` | Кількість документів, термінів, токенів та час роботи |
| GET | `/health` | HTTP 200, якщо індекс готовий; інакше HTTP 503 |
| GET | `/` | Україномовний HTML-пошук із підсвічуванням і пагінацією |
| GET | `/doc/{doc_id}` | HTML-сторінка документа |
| GET | `/docs` | Інтерактивна документація FastAPI |

Відповідь `/search` має поля `query`, `total`, `took_ms`, `results`, а кожен результат містить `doc_id`, `title`, `score`, `snippet`. Обмеження параметрів перевіряє Pydantic/FastAPI — помилки мають статус **422**. Помилки парсингу пошукового синтаксису повертають 400. Неочікувані помилки протоколюються з ідентифікатором запиту, а клієнт бачить узагальнену 500.

### Приклади

```bash
curl 'http://127.0.0.1:8000/search?q=python&k=5'
curl 'http://127.0.0.1:8000/search?q=python&k=abc'  # HTTP 422
curl 'http://127.0.0.1:8000/docs/999999'             # HTTP 404
```

## 3. Архітектура

```
src/findex/
  cli.py               — команда serve (плюс сумісність з попередніми CLI)
  web/
    app.py             — FastAPI, Pydantic, Depends, lifespan, API та HTML
    templates/
      index.html       — форма пошуку, результати і пагінація
      document.html    — перегляд документа
    static/style.css   — оформлення адаптивної сторінки
  index.py, ranking.py, store.py та інші — пошукове ядро

scripts/benchmark_lab07.py — 20 конкурентних запитів у пам'яті
LAB07_LOCAL_BENCHMARK.csv — вимірювання на тестовому корпусі
Dockerfile              — двоетапне складання, запуск не від root
render.yaml             — приклад розгортання на Render
tests/test_web.py        — тести API, HTML, конфігурації та життєвого циклу
```

Індекс завантажується один раз у `lifespan` і закривається під час зупинки програми. У тестах підмінюється через `app.dependency_overrides[get_index]`. Налаштування читаються з `pydantic-settings`: `INDEX_PATH`, `LOG_LEVEL`, `PORT`, а також `.env`.

**Рішення щодо синхронності.** Маршрут `/search` оголошено через `def`, оскільки індексатор і обчислення BM25/TF-IDF синхронні й можуть блокувати цикл подій. FastAPI запускає такий обробник у пулі потоків. `async def` з таким самим синхронним кодом може бути швидшим лише за малого навантаження, але ризикує блокувати інші запити.

## 4. Перевірки

```bash
python -m pytest -q
python scripts/benchmark_lab07.py
```

Перевірено: успішний пошук, TF-IDF, пагінація, 422 для некоректних аргументів, 404 для невідомих документів, 503 при відсутності індексу, сторінка `/docs`, вебінтерфейс, безпечне екранування HTML, завантаження індексу під час запуску та звільнення ресурсів.

## 5. Локальний експеримент із 20 запитами

Дані з `LAB07_LOCAL_BENCHMARK.csv`. **Це ASGITransport у пам'яті без мережі, не `oha` і не вимірювання на сервері.** На коротких запитах накладні витрати на пул потоків можуть перевищити сам час пошуку.

| Режим | Одночасних запитів | RPS | p50, мс | p95, мс | p99, мс |
|---|---:|---:|---:|---:|---:|
| `def` | 20 | 292.15 | 52.859 | 58.324 | 58.324 |
| `async def` (синхронне ядро) | 20 | 932.21 | 17.476 | 19.418 | 19.418 |

Ці числа залежать від середовища та короткості запитів. За реального CPU-навантаження синхронні обчислення всередині `async def` блокують цикл подій; тести з іншим обсягом і числом процесів можуть змінити картину. GIL обмежує виконання CPU-коду потоками, а окремі процеси Uvicorn дозволяють задіяти декілька ядер.

### Вимірювання, які потрібно зробити після розгортання

```bash
# Запустіть сервер локально, після цього встановіть oha.
oha -z 30s -c 50 'http://127.0.0.1:8000/search?q=python'
# Інший термінал: зупиніть сервер і запустіть 4 процеси.
uv run findex serve --port 8000 --workers 4
oha -z 30s -c 50 'http://127.0.0.1:8000/search?q=python'
# Повторіть з -c 20 для вашого публічного URL.
```

| Середовище | Паралельність | RPS | p50 | p95 | p99 |
|---|---:|---:|---:|---:|---:|
| localhost, 1 процес (`def`) | 50 | — | — | — | — |
| localhost, 1 процес (`async def`, експериментальний варіант) | 50 | — | — | — | — |
| localhost, 4 процеси | 50 | — | — | — | — |
| Опублікований сервер | 20 | — | — | — | — |

Позначка «—» означає, що **результат не вимірювався**. Експериментальний async-варіант для 20 запитів доступний у `scripts/benchmark_lab07.py`; для мережевого порівняння `oha` потрібен тимчасовий маршрут `async def` замість робочого `def`.

## 6. Docker і розгортання

```bash
docker build -t findex:lab07 .
docker run --rm -p 8000:8000 findex:lab07
```

Dockerfile використовує двоетапне складання та створює демонстраційний індекс усередині контейнера. Вебпроцес працює без прав root. **Docker тут не запускався**, тому фактичне складання контейнера треба перевірити на ПК.

Для публікації створіть репозиторій на GitHub, завантажте цей проєкт, підключіть його до Render із `render.yaml`, перевірте `/health` та додайте отримане посилання сюди:

**Публічний URL:** _ще не створено_.

## 7. Висновок

Поєднано пошукове ядро з REST API та HTML. Практично застосовано модель ASGI, перевірку типізованих параметрів, ін'єкцію залежностей, керування життєвим циклом сервісу і тестування HTTP-взаємодії. Основні маршрути можна продемонструвати локально; повна відповідність вимозі про публічне розгортання потребує власного сервера.
